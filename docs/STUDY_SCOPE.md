# الشعبة، مادة المحادثة وهوية المصادر

## حساب الطالب

- عند أول دخول يختار الطالب شعبته من ستة خيارات ثابتة: علوم تجريبية، رياضيات، تقني رياضي، تسيير واقتصاد، آداب وفلسفة، لغات أجنبية.
- الاختيار إلزامي قبل إنشاء المحادثة أو إرسال السؤال. يُحفظ في `users.study_track`، لا في تفضيلات الشرح. الطلبات اللاحقة بنفس القيمة idempotent؛ محاولة تغييرها أو مسحها مرفوضة، ويمنعها trigger في SQLite أيضًا.
- الحسابات القديمة ذات الشعبة الفارغة تمر بنفس الشاشة. لا نستنتج شعبة من نص التفضيلات القديم، ولا نفرض شعبة تلقائيًا.
- زر **المادة** أعلى المحادثة يعرض مواد الشعبة المختارة فقط. لا اختيار افتراضي صامت للمادة.
- قبل أول رسالة يمكن تغيير مادة المحادثة الفارغة. بعد وجود أي رسالة، حتى رسالة غير نشطة بعد التعديل، اختيار مادة أخرى ينشئ محادثة جديدة؛ تبقى السابقة وسجلها محفوظين.
- لا تُنسخ الرسائل أو المراجع المحمّلة أو الملفات الخاصة إلى المحادثة الجديدة. التشغيل القديم إن كان جاريًا لا يُلغى ضمنيًا.
- المحادثات القديمة بلا مادة تظل قابلة للعرض. إذا كان فيها تاريخ، أول اختيار للمادة ينشئ محادثة جديدة بدل نسبة التاريخ القديم إلى المادة المختارة.

القائمة ملك للخادم في `bac/core/study.py`. هذه خيارات المنصة المحددة وليست ادعاء بمراجعة جميع تغييرات المنهاج الرسمي الحالية. تُعرض مواد الهندسة الأربع تحت تقني رياضي واللغات الأجنبية الثلاث تحت لغات أجنبية؛ لم تُضف شاشة مستقلة لاختيار تخصص هندسي أو لغة ثالثة.

## حماية المصادر

`StudyScope` يستمد الهوية من الحساب والمحادثة في قاعدة البيانات، وليس من نص الطالب، أو قرار LLM، أو تفضيلات اللغة والأسلوب.

- فهرس الراوتر والبحث وقائمة المستندات تُفلتر بالشعبة **والمادة** قبل الفرز أو الحد العددي.
- قراءة الدرس والأجزاء والحزم والصفحات والأصول تعيد التحقق من نطاق المستند قبل إعادة محتواه.
- معرّف ملف من خارج النطاق لا يفتح المصدر، حتى لو عرفه النموذج أو حُقن في `loaded_context`؛ السياق القديم المرفوض لا يُعاد تسليمه.
- تفضيلات الشرح والتجاوزات لا تغيّر الصلاحيات. لقطة المدرّس تفرض الشعبة والمادة الحقيقيتين بدل نصوص التفضيلات القديمة.
- بعض أسماء الشعبة والمادة القديمة المعروفة، مثل `science` و`فيزياء`، تُحل إلى الهويات المحددة. لا مطابقة تقريبية لاسم غير معروف؛ يُراجع المالك هوية المصادر غير المصنفة ثم يعيد اعتمادها ونشرها.
- حسابا المالك والأستاذ يحتفظان بسير الإدارة/الاختبار السابق؛ قيد حساب الطالب هو الذي يُطبق هنا. واجهات المصادر العامة تظل خاصة بالمالك كما كانت.

## رفع المحتوى

**الشعب المستهدفة** مجموعة اختيارات ثابتة تسمح بتحديد شعبة واحدة أو عدة شعب لنفس المستند. تشمل استمارة الرفع ومحرر هوية المسودة وبيانات الحل، بدل الحقول الحرة. المادة تعرض فقط الخيارات المشتركة بين جميع الشعب المحددة؛ لا يمكن حفظ كتاب في مادة غير متاحة لإحدى شعبه.

يُرفع الكتاب مرة واحدة ويحتفظ بهوية مستند وPDF وفهرس واحد؛ كل طالب من الشعب المحددة يستطيع الوصول إليه ضمن مادة المحادثة فقط، ولا يرى الشعب غير المستهدفة أو المواد الأخرى. تظل شعبة حساب الطالب اختيارًا واحدًا ثابتًا.

لإضافة شعب إلى كتاب **منشور سابقًا**: إنشاء نسخة جديدة ← تعديل هوية المسودة ← تحديد الشعب ← حفظ الهوية ← اعتماد المراجعة والنشر. تستخدم النسخة الجديدة الاستخراج المكتمل نفسه؛ لا يلزم رفع PDF مرة أخرى أو تشغيل المعالجة من جديد. تغيير جمهور المسودة لا يغير صلاحيات النسخة المنشورة قبل اعتمادها ونشرها. إزالة شعبة من النسخة المنشورة الجديدة تمنع طلابها من القراءة.

تُحفظ قائمة `tracks` في metadata. الحقل القديم `track` يبقى كأول قيمة للتوافق فقط، ولا يحصر المصدر في شعبة واحدة. المصادر القديمة بلا قائمة تستعمل شعبتها السابقة دون إعادة كتابة اللقطات أو ترحيل بيانات جديد.

الحل المرفق يرث جميع شعب الموضوع عند الرفع معًا. تتطلب مطابقة الحل نفس **مجموعة الشعب**، وليس ترتيبها أو أول شعبة فقط. تغيير المجموعة يبطل توثيق المطابقة السابق كأي تغيير في هوية المصدر.

أربعة أنواع محتوى:

1. كتاب مدرسي (`textbook`).
2. فروض واختبارات (`school_tests`).
3. تمارين (`exercises`).
4. امتحانات البكالوريا (`bac_exams`).

تُحفظ فئة المحتوى مستقلة عن نوع التخزين الداخلي القديم. تتوافق الكتب المرجعية القديمة مع `textbook`، لكن لا يظهر خيار خامس للرفع الجديد.

لغير الكتب، يمكن رفع الموضوع وحده، أو الموضوع والحل في طلب واحد:

- **PDF واحد:** يحدد المالك نطاقي صفحات الموضوع والحل، بالأرقام الفعلية في PDF لا ترقيم الكتاب المطبوع. يلزم أن يكونا ضمن الملف وغير متداخلين؛ لا يخمّن LLM بداية الحل.
- **ملفان:** يرفع الموضوع وPDF الحل معًا. يربطهما الخادم في نفس الإصدار بدوري `primary` و`solution`؛ النطاق الافتراضي هو كامل كل PDF.
- يلزم تأكيد أن الحل يخص الموضوع نفسه. هوية الشعبة والمادة والسنة والدورة تؤخذ من بيانات الموضوع. الحل يبقى `provided/pending`، ولا يصبح رسميًا أو موثّق المطابقة لمجرد الرفع.
- يُفحص الملفان والنطاقان قبل إنشاء إصدار المنصة. إذا تعثر الربط تُزال سجلات الإصدار الجديد وحدها، لا الإصدارات السابقة. قد تبقى نسخة خام صالحة في cache الاستخراج للتكرار؛ لا تُحذف ملفات مشتركة ولا تدخل الفهرس المنشور.
- حد الحجم ينطبق على كل PDF؛ سقف الطلب الكامل يتيح ملفين إضافة لهامش multipart، ولا يرفع سقف الملف الواحد.
- تبقى المعالجة، مقارنة الحل، توثيق مطابقته ومصدره، ثم مراجعة النسخة ونشرها إجراءات صريحة للمالك. الرفع لا يشغّل OCR أو نموذجًا مدفوعًا ولا ينشر المحتوى تلقائيًا.

## ما يصل إلى راوتر LLM

ضمن نطاق الطالب فقط:

- الكتب: الفهرس المنشور الكامل، بما فيه الوحدات والدروس والعناوين الفرعية الحقيقية وصفحات PDF.
- الفروض والاختبارات والتمارين والبكالوريا: عنوان/اسم المستند ونوعه وصفحاته، لا فهرسة مصطنعة لأسئلته كدروس.
- عند طلب تمرين/اختبار يختار الراوتر الحزمة الكاملة. القراءة اللاحقة تجلب الموضوع والحل المطابق إن كان قد اعتمد ونشر، ثم يتحقق الراوتر من التغطية الفعلية.
- البرومبت يصرح بالنطاق الثابت وبالتمييز بين درس نظري وملف تطبيق. الفهرس لا يتيح مصادر مادة ثانية حتى لو طلبها الطالب في نفس المحادثة.

## تحديث نسخة Docker موجودة

خذ نسخة احتياطية متناسقة تشمل مفاتيح التشفير، ثم حدّث Git وأعد بناء API وworker بنفس ملفات Compose ووحدات البيانات المستخدمة فعليًا. إذا كنت تستخدم `compose.schoolbook.yaml` فاحتفظ به ضمن الأمر؛ وإعداد الإنتاج يحتفظ بملفه أيضًا.

مثال **فقط إذا كنت تستخدم ملف الكتاب المذكور**:

```bash
git pull --ff-only
docker compose -f compose.yaml -f compose.schoolbook.yaml up -d --build api worker
```

بدون override الكتاب، استعمل ملف التشغيل الفعلي نفسه بدل اختراع ربط بيانات جديد. لا تستخدم `down -v`. يتم تطبيق migration 009 تلقائيًا عند بدء الخدمات. لا تُحذف المكتبة، ولا يلزم تنزيل ZIP أو إعادة استخراج الكتاب. حدّث المتصفح بعد البناء.
