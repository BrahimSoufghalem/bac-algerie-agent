# Learning context — agent-managed notes, private files and role-scoped teaching

## A single agent, role-scoped tools

Published retrieval is unchanged: metadata/identity → actual TOC → complete short lesson or stable complete-element parts. Exams and exercise collections remain whole logical bundles, including their supplied/owner-matched solution. Do not put the whole library in the model context. See [RETRIEVAL.md](RETRIEVAL.md).

Students, teachers and owners use the **same AgentEngine and scientific runner**; approved owner references are private model-only context, not a student/teacher library. Public registration creates only students. Only owners assign teachers, roles and limits. A teacher cannot read another student's conversations, private files, notes, scientific results or teaching drafts; owning the platform is not permission for these private API reads either. Database administrators with physical access can inspect server storage: this is authorization separation, not end-to-end encryption.

Teacher tasks: `lesson_plan`, `exercise_set`, `exam`, `grading`, `reference_review`; student self-practice storage and its tool are retired. The UI starts an explicit ordinary agent run. `save_teaching_material` saves private generated drafts; There is no student material-saving tool. Saved content uses the same source/image/science validation as final answers. Tests require a **separate solution and rubric**; marks sum to `total`; grading requires awarded marks ≤ maximum. Insufficient grading inputs must prompt a question, not invented marks. Generated drafts always have `official=false`, `review_status=draft`; storage is not educational certification. View/export/delete own drafts in the UI. A real provider must support tool calling; automated fixtures prove tool wiring, not the quality/completeness of generated lesson plans or grading.

## Preferences and agent-managed read-only notes

Preferences remain typed untrusted data, not policy or permission overrides. `include_approved_notes` is a deprecated compatibility field: it neither enables nor disables current agent-owned memory and has no UI control. Enqueue snapshots at most six own active `origin=agent` observations. Legacy user-written notes are never promoted into agent memory.

`write_learning_note` creates/updates a tentative weakness/mistake/mastery/goal based on demonstrated behavior; `delete_learning_note` removes an obsolete/incorrect observation. Both require an active own run and active account. Only own agent-origin IDs may be changed, at most 100 notes. The system prohibits sensitive personal traits, policy instructions, copied reference passages and student requests to fabricate mastery or erase demonstrated mistakes. Model compliance is tested but not a guarantee of perfect educational judgement.

`GET /api/notes` returns only agent-origin notes with `read_only=true`; POST/PUT/DELETE are forbidden for all browser roles. Notes are available under account settings, not primary navigation. Updates/deletes scrub stale persisted snapshots; already sent model data cannot be recalled. Account erasure removes notes together with the user's other data. No note-edit/consent workflow remains in the app.

## Ephemeral private chat files

`POST /api/conversations/{id}/upload` accepts an actual PDF/image/TXT, not URL fetching. No HTML/SVG/archives. Limits: **10 MB/file, five active files/user, 20 pages/PDF, 24 hours**, images ≤12 million pixels, text UTF-8/no NUL/≤20000 characters. PDFs are inspected and rasterized through the existing resource-limited PyMuPDF subprocess; no OCR/Vision request at upload time. Scanned pages are later delivered as actual multimodal image input to the teaching model, not as a guessed caption or OCR primary source.

`list_private_uploads` lists only own, unexpired files in this chat. `read_private_page` reads a single page: full bounded text, or server-rendered JPEG pixels with a private source ID. Engine caps four images and six MB of JPEG bytes per run, two MB per image; full base64 is **never persisted in DB/SSE/logs** or counted as ordinary text. Normal tool/text context caps still apply. Source/image credit is granted only after bounded data/pixels enter the run context. Private source IDs remain internal; image/citation links are not displayed in answers. A filename/caption alone does not grant visual inspection credit. If the teaching model lacks vision, it must state inability rather than fabricate text.

Own API:
- `GET /api/conversations/{id}/uploads`
- `GET /api/private/{upload_id}/original` (attachment)
- `GET /api/private/{upload_id}/pages/{page}` (raster or text JSON)
- `DELETE /api/private/{upload_id}`

Files are outside shared BookForge storage, published nodes and full-text indexes: `data/private/<opaque-upload-id>/`. There is no automatic publication, cross-user cache or shared search. All reads require ownership, active session and current expiry; API sends `Cache-Control: no-store`. Deletion/expiry cancels affected active chat runs. A worker sweeps every 30 seconds; upload also sweeps expiry. **Reads deny expired content immediately**, even before physical cleanup. If worker/server is off, physical removal waits for restart/next sweep; retain storage securely and monitor it. A process crash may leave partial staging/render files; production orphan sweeps/storage quotas and hostile-parser evaluation remain part of Phase 5. Closing the browser doesn't stop the worker. A file TTL does not erase already-produced chat text or data already sent to a provider.

## Export and deletion

`GET /api/privacy/export` downloads own profile/preferences/agent notes/teacher drafts/sanitized chats and unexpired file metadata; secrets, provider configuration and sessions are excluded. Binary originals must be downloaded separately before expiry. Refuse oversized export (500 chats, bounded message size, 10 MB final JSON) instead of silently truncate. `GET /api/conversations/{id}/export` is an individual chat JSON. UI offers export and password-confirmed account erasure. Account erasure removes chats/runs/scientific results/notes/drafts/usage and private filesystem files. Active runs are cancelled first; retry after they stop. Owner/content-owning or review-attributing accounts need administrative ownership transfer and cannot self-erase via this endpoint. This release does not automate content ownership transfer. Chat deletion cleans its own private files but keeps independent agent notes and teacher drafts; only the agent manages notes, and account erasure removes them.

## Owner controls and actual accounting

Chat history and both export paths include sanitized per-answer work summaries reconstructed from saved events. They are not model reasoning, raw tool logs or reference provenance. Fixed generic labels/states attach by actual answer-message ID; later questions do not replace earlier summaries. Legacy messages without saved events receive no fabricated record. See [current work UI acceptance](acceptance/per-answer-work-ui.md).

`GET/POST /api/owner/accounts`, `PATCH /api/owner/accounts/{id}`: paginated/searchable accounts (50/page), teacher/student creation, role/active state, daily run allowance (rolling 24h; **0 disables**), observed token allowance, messages/minute, concurrent runs, estimated-cost alert. Last active owner cannot be removed. Role/active changes revoke sessions; any changed limits cancel active runs. Audit records previous/new role/limits without passwords/API keys. No user chat/notes/preferences are returned by account administration. Email verification and password recovery retain their configured-mail flows; external source service tokens are retired.

Account run/token/concurrency limits govern the teaching agent, not a BookForge extraction batch. Extraction retains its own page queue, worker/retry/rate controls; its actual calls still appear in accounting. Do not treat account limits as a global extraction billing cap.

Default one active run per user; transaction-safe admission across chats. Limits check fresh account state, not stale caller data. Message submission and retry are bounded; run retries count toward allowance and are never hidden paid retries. Token allowance is checked **before each new provider request**, using reported input+output tokens from the previous rolling 24h. Missing usage fails closed if a token limit is set. One or more allowed in-flight requests may overshoot before reporting; this is NOT a strict provider billing cap. Daily run and output/context/image/time controls (no fixed model-round or total tool-call cap) provide separate controls. Estimated-cost alert is informational, not an automatic payment ceiling.

`GET /api/usage` is personal. `GET /api/owner/usage?days=30` aggregates actual requests by model/feature and bounded period (1–365 days), token/cache counts, latency, errors, missing usage/cache/cost, run counts; internal tool-call counters are never returned by usage APIs. Extraction is metered by a wrapper **only when an actual Vision request occurs**; reuse of successful pages/raw JSON/crops/source cache is not billed as a new call. Wrapper keeps vendor files unchanged. Configuration IDs and prices are immutable snapshots; changing UI prices doesn't retroactively recalculate history. Failed attempts are requests too; missing usage remains null. No provider price assumptions or invented token counts.

Prices per million input/output/cached input are owner supplied in the model UI; specify your own billing currency consistently. With usage+input/output prices, missing cache reporting/pricing uses ordinary input price as a labelled upper-price estimate, not an invoice; if required tokens/prices are missing, cost is unavailable. Provider-reported `cached_tokens` is distinct from local immutable-file-cache hit/miss/eviction/bytes metrics. No cross-user answer cache exists. Published-file authorization and current publication are checked before cache lookup; revocation still prevents reads.

`POST /api/owner/models/{agent|extraction}/test` requires `confirm=true` and an explicit click. It performs **GET /models only**, with safe URL validation, no redirect/environment proxy, 10s deadline, 256 KB response cap, three tests/minute. Secrets and provider error bodies aren't returned or logged. It checks reachability/authentication and advertised model identity, NOT vision/tool capability, teaching quality or pricing. Some compatible providers don't implement model listing; a failed listing doesn't prove their chat endpoint is unusable. No implicit paid generation at save/navigation/upload; an actual teaching/extraction run is the cost-incurring action.

## Deployment/verification limits

This is single-host Linux/SQLite/local-disk architecture. Migrations are serialized using a Linux file lock during API/worker startup. Private-file cleanup runs with the worker; persistent TTL file deletion requires the services to run. Back up DB/files/encryption key consistently, protect data directory, use HTTPS/secure cookies before external access. Full native parser audit, quotas/orphan sweep/load testing, privacy retention policy, provider quality testing, backups/restore and production acceptance remain Phase 5. New visual inspection is pending if the image tool is unavailable; functional browser assertions are not a visual approval.

## Actual-read evidence and retry recovery

Teaching runs and generated teaching materials now require selected actual delivered read evidence, not locator snippets or unstructured model prose. Missing evidence requires a bounded clarification, not an unsupported general lesson. The read gate is structural provenance enforcement, not semantic entailment/automatic topic-relevance certification. Simple social exchanges and actual standalone computations have separate bounded routes.

History/export also preserve earlier failed attempts after a successful retry. Cached source reload is a fresh scoped content read and has its own generic stage. Prior real equations/tables are included in follow-up model context, without converting old scientific results into current-run proof. Operator diagnostics remain local-only and scrubbed, never part of public activity. See [acceptance](acceptance/grounded-teaching-recovery.md).
