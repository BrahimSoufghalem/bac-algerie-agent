# تصميم مسار: المحادثة أولًا

أُعيد بناء shell المحادثة ومربع الكتابة والتنقل، وليس إضافة ألوان فوق لوحة الإدارة القديمة. تجربة مستوحاة من واجهات ChatGPT/Claude/Notion AI مع هوية مسار مستقلة وعربية RTL. تفاصيل مراجعة المستودعات والتراخيص في [THIRD_PARTY.md](THIRD_PARTY.md).

## النظام البصري
- Canvas عاجي هادئ، sidebar منفصل قليل التباين، أسطح ورقية ومظهر داكن متكافئ؛ الرمادي الدافئ مع لون ترابي صغير في العلامة، لا بطاقات لوحة تحكم في المحادثة.
- Noto Sans Arabic محلي، SVG خطية محلية أصلية، بلا أيقونات Unicode ناقصة أو طلبات avatar/CDN خارجية. عرض القراءة 800px شاملاً الهوامش، نص طويل واضح، معادلات KaTeX والجداول والرسوم التوضيحية المولّدة. لا صور المصدر أو أدلة التنفيذ.
- حقل كتابة عائم مستدير مع زر إرسال/إيقاف؛ يظهر في وسط الشاشة الفارغة وتحت الردود في المحادثة. يكبر تلقائيًا إلى 180px، ثم يتمرّر داخليًا.
- رسالة المستخدم bubble صغيرة، رد الوكيل دون بطاقة؛ نسخ الرد وتعديله وإعادة المحاولة أدوات فعلية وليست زخرفة. المقترحات تعبئ المسودة فقط ولا ترسل طلبًا مدفوعًا.

## أين أجد الوظائف؟
- الشريط: محادثة جديدة، بحث المحادثات وسجلها؛ إعداد الأستاذ للأستاذ/المالك فقط. المكتبة والتدريب الذاتي محذوفان.
- **اسم المستخدم أسفل الشريط / إعدادات الحساب**: الخصوصية، أمان الحساب، استخدامي وحدودي، المظهر والخروج. للمالك أيضًا المحتوى، النماذج، الاستخدام والحسابات. ملاحظات مسار التعليمية هنا للقراءة فقط. صلاحيات المصدر في الخادم صارت خاصة بالمالك.
- زر مشبك الورق: ملفات خاصة مؤقتة 24 ساعة؛ نافذة بهوية مسار مع اختيار ملف/سحب وإفلات، قائمة المرفقات والتنزيل والحذف وشرح الحدود والخصوصية والتكلفة. يمكن الإرفاق من المحادثة الفارغة دون استدعاء النموذج أو محو المسودة. Escape والنقر خارجها يغلقانها. اختيار ملف يستخدم منتقي النظام؛ لا يظهر نموذج HTML بدائي داخل النافذة.
- لا chips للمراجع، ولا reading sheet للطالب أو الأستاذ، ولا لوحة تفاصيل أدوات. المالك فقط يعاين مصادره في إدارة المحتوى، وليس عبر جواب الوكيل.
- أسفل الشريط بطاقة حساب واضحة بزر إعدادات SVG، وقائمة برأس حساب ومجموعات وظائف ومظهر. فتح وإغلاق هادئان؛ العناصر المغلقة inert ولا تدخل تنقل لوحة المفاتيح.
- خيارات المحادثة: إعادة تسمية/حذف داخل dialog مؤكد، لا native prompt/confirm. الأثر محفوظ عبر API وقاعدة البيانات.

## درج مراحل الإجابة
- الموضع: **سؤال المستخدم ← درج مراحل هذه الإجابة ← رد مسار**. ليس أسفل الرد ولا قائمة مشتركة تُمسح مع السؤال التالي.
- لكل تشغيل هوية مستقلة؛ يربط الخادم الملخّص برسالة الرد الفعلية المسجّلة في حدث answer. يُعاد بناؤه من run_events المحفوظة عند فتح المحادثة أو التصدير، دون migration إضافي. لا يُختلق سجل لرسالة قديمة بلا أحداث محفوظة.
- أثناء التنفيذ تتحدّث المراحل الحقيقية، وبعد الرد تبقى قابلة للفتح والإغلاق. يحتفظ الطلب المتوقف بملخّصه تحت السؤال بعد إعادة الفتح. حالة الفتح اختيار محلي للواجهة وليست بيانات تعلم.
- labels ثابتة مُجازة مثل «حساب القيم» و«مراجعة الأبعاد»، لا كلام النموذج أو التفكير الداخلي أو أسماء الأدوات أو تفاصيل المراجع أو arguments/results. اكتمال المرحلة لا يصدّق على كل الشرح؛ الفحص غير الناجح لا يحمل علامة نجاح.
- كشف وإخفاء بحركة grid/opacity هادئة، مؤشر تنفيذ خفيف وخط زمني محدود الارتفاع. يُحترم reduced motion، ولا يفرض فتح الدرج تمريرًا إلى نهاية المحادثة.

## التفاعل والوصول
- Sidebar قابل للطي على الحاسوب مع rail، وdrawer على الهاتف. عرض 360، 390، 768 و1440px ضمن فحوص المتصفح.
- Tab/focus trap وEscape للنافذة وdrawer، inert للخلفية، focus restoration، labels وtooltips لأزرار SVG، رابط تجاوز إلى المحتوى دون تغيير URL المحادثة.
- Enter يرسل، Shift+Enter لسطر جديد؛ Enter أثناء IME composition لا يرسل. حذف المرفق زر type=button كي لا يرسل المسودة خطأ.
- Auto-scroll فقط عندما يكون المستخدم قريبًا من نهاية الرد؛ قراءة الرسائل السابقة لا تقطعها تغييرات الرد. زر واضح للعودة إلى أحدث رسالة.
- فاتح/داكن/تلقائي حسب النظام، احترام reduced motion. localStorage للمظهر وطي الشريط فقط؛ لا مفاتيح API أو رسائل أو أدوار فيه.
- الأخطاء والتحذيرات التعليمية العامة تبقى واضحة دون رموز تقنية أو تفاصيل أدوات أو أسماء مراجع. الدرج ملخّص عمل حقيقي، لا fake thinking ولا عرض للتفكير الداخلي. لا model picker غير متصل بمحرك حقيقي ولا أزرار صوت وهمية.

## حدود الإثبات
اختبارات DOM/الوظائف والهاتف واللقطات ليست مراجعة بصرية بشرية. ينتج tests/browser/helpers.ts ملفات PNG/HTML بعد اكتمال الخطوط والحركات المحدودة، مع إخفاء secret password inputs. فُحصت لقطات التحسين الحالي بأداة عرض الصور، لكن يبقى قبول المستخدم للتصميم مطلوبًا؛ هذا ليس اعتمادًا بصريًا مستقلًا.

لم تُجرَ استدعاءات مزوّد مدفوعة جديدة في تحسين الدرج والشريط والمرفقات. استعادة ردود المزوّد الحقيقية السابقة لتصوير الواجهة ليست تجربة نموذج جديدة. تقارير المراحل السابقة تاريخية؛ راجع [التقرير الحالي](acceptance/per-answer-work-ui.md). هذه المرحلة لا تعني اكتمال بوابات الإطلاق في OPERATIONS.md/ROADMAP.md.

GitHub Actions يحفظ PNG للمراجعة في artifact باسم ui-design-previews لمدة 14 يومًا، بما في ذلك عند نجاح الاختبارات. المصادر المعروضة fixtures صناعية محلية وليست كتب المالك أو مفاتيحه.
