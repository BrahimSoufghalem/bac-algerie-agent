# اختبار الرياضيات الحقيقي عبر GitHub Actions

هذا تشغيل تشخيصي يدوي، وليس نشرًا للمنصة أو إصلاحًا تلقائيًا للمشاكل. لا تحتاج Docker على جهازك. تستخدم المهمة نسخة GitHub المؤقتة، وخدمة Python الإنتاجية المعزولة في المشروع، وملف الرياضيات الأصلي، والأسئلة الـ24 نفسها في محادثة واحدة.

## الإعداد مرة واحدة

1. يجب دمج ملف التشغيل في الفرع الافتراضي `main` أولًا؛ لن تعمل المهمة من فرع آخر.
2. افتح مستودع `bac-algerie-agent` → **Settings → Secrets and variables → Actions → New repository secret**.
3. الاسم بالضبط: `GEMINI_API_KEY`.
4. في خانة **Secret** ضع مفتاح Google AI Studio / Gemini، ثم **Add secret**. لا تضع المفتاح في الكود، Issues، PR، أو المحادثة.

## التشغيل

1. افتح **Actions → Gemini mathematics live benchmark → Run workflow**، واختر `main`.
2. يمكن تشغيل `mode: preflight` أولًا. يبني الحاويات ويفحص خدمة Python، ولا يرسل أي طلب إلى Gemini ولا يحتاج مفتاح Gemini.
3. للتجربة الحقيقية اختر `mode: live` وفعّل مربع **confirm_live** للموافقة على استهلاك API. تُنفَّذ الأسئلة الـ24؛ مفتاح Gemini نفسه يستخدم للراوتر ونموذج الإجابة `gemini-3.5-flash-lite`.
4. عند النهاية افتح ملخص المهمة، ثم حمّل المرفق `gemini-math-evidence-…`. يحتوي `report.md` و`evidence.json` والإجابات والطلبات المنقحة ونتائج الأدوات والمراجع. الملفات محفوظة 7 أيام.
5. أرسل رابط التشغيل أو مرفق النتائج للمراجعة التفصيلية. نجاح المهمة يعني اكتمال التشغيل، **لا** صحة كل شرح أو رسم. ستبقى المشاكل للمناقشة ولا تُصلَح تلقائيًا.

## حدود الاستهلاك والسلامة

- التشغيل يدوي فقط، لا يعمل عند `push` أو `pull_request` أو على جدول زمني. الوضع الافتراضي `preflight`؛ الاستدعاءات الحقيقية تتطلب `live` وموافقة صريحة.
- حد التجربة 128 طلب توليد. التوقف عند بلوغ 2.5 مليون **توكن إدخال مبلّغ عنه** حدّ مراقبة مرن: قد يتجاوزه الطلب الجاري؛ ليس وعدًا بحد فوترة دقيق أو سقف سياق جديد للمنصة.
- لا إعادة محاولة HTTP تلقائية. تتوقف التجربة عند 401/403/429، أو عند غياب عدادات الاستخدام لردين ناجحين. قد تكون بعض حالات الفشل بلا عداد استخدام؛ التقرير يبيّن المجهول بدل اعتباره صفرًا.
- الكاش جزء من الإدخال، والتفكير لا يُضاف مرة ثانية إلى إجمالي الإخراج. أسعار الفوترة غير مهيأة، فلا يُخترع تقدير مالي.
- لا تُرسَل أسرار GitHub أو مفتاح Gemini أو قواعد بيانات المنصة إلى حاوية تنفيذ كود النموذج. خدمة الوسيط وحدها تملك Docker socket، ويُتاح منفذها على loopback فقط؛ الحاويات المنفذة بلا شبكة وبجذر ملفات للقراءة فقط وحدود موارد.
- تُحفَظ النتائج الجزئية عند فشل/توقف التشغيل إذا أُتيحت خطوة التصدير. المفاتيح وقاعدة بيانات الاختبار ومفتاح تشفيرها خارج قائمة التصدير، وتُحذف قبل رفع المرفق.
- المستودع **خاص**. النسخة المضغوطة من الكتاب ليست مشفرة؛ لا تغيّر المستودع إلى عام قبل إزالة ملف المصدر وبياناته من تاريخ Git أو مراجعة حقوق نشرها. اختبار الخصوصية يمنع تشغيل المهمة على مستودع عام، لكنه لا يمحو ملفًا منشورًا سابقًا.
- قد يخضع GitHub Actions لحصة أو رسوم حسابك، واستهلاك Gemini لحصة/فوترة مفتاحك. لا تُوصَف التجربة بأنها مجانية بلا تحقق من حسابك.

## ما يُفحَص وما يحتاج مراجعة

تسجّل التجربة مدخل الراوتر الكامل، اختيار المرجع وتسليمه، الأدوار والسؤال الحالي، كل طلب مزوّد وعداد استخدامه، كل استدعاء أداة ونتيجته، رفض الإجابات، والجواب المنشور. يسجّل التقرير إشارات مثل أخطاء Python، حالة checks، كتل الرسم، وبعض أوامر LaTeX المزدوجة.

`COMPLETED` يعني نشر جواب. `computed` يعني تنفيذ كود النموذج. وجود كتلة رسم لا يثبت أنها المنحنى الصحيح. نجاح check كتبه النموذج لا يغني عن التحقق المستقل. راجع جودة الشرح، تكافؤ الاحتمالات، حدود المجالات، وصل فروع الدالة، الأخطاء المنسوبة للطالب، وحالة السؤال M23 دون مرفق.
