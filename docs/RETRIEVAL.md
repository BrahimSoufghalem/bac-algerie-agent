# الاستدعاء في مسار: إعادة استخدام BookForge مع تصحيح حدود السياق

## القرار

BookForge مناسب كأساس: مصدر PDF محفوظ، صور صفحات، JSON، نص كامل، صور أصلية مقصوصة، معادلات وجداول، وحدود عناصر مرتبة. أُعيد استخدام محركه كما هو، **دون تعديل المشروع الأصلي أو نسخة vendor**. تغيّرت طبقة النشر والاستدعاء في مسار فقط.

لا نزعم أن هذه أفضل خوارزمية لكل مكتبة أو أن BM25 يتفوق على vector search في جميع الحالات. القرار الأنسب لهذه المتطلبات حاليًا: **هوية المصدر → بحث مفلتر → هيكل فعلي → أصغر محتوى كامل يكفي**. يلزم benchmark على كتب حقيقية قبل تبديل طبقة البحث أو الادعاء بتحسن دقة نموذج فعلي.

| المشكلة في المسار الأول | التنفيذ في المرحلة الثانية |
|---|---|
| استدعاء metadata كان يقرأ Markdown كاملًا | قراءة metadata فقط بلا I/O للمحتوى؛ cache مشترك محدود بالحجم والعدد وTTL |
| قياس طول content وحده | فحص JSON الناتج كاملًا قبل منحه citation credit |
| context restore قد يسجل مصدرًا ثم لا يرسله | لا يُسجّل المصدر إلا بعد قبول إدراجه في الرسائل |
| درس طويل بلا أقسام فعلية قابل للاستدعاء | أجزاء ثابتة عند حدود **عناصر كاملة**، دون قطع فقرة أو جدول أو LaTeX؛ عنصر منفرد زائد يُرفض ولا يُبتر |
| طبقات الكتاب تكرر الجسم نفسه في BM25 | فهرسة النص المباشر للعقدة، واستبعاد جسم descendants المكرر؛ جميع العقد تبقى قابلة للقراءة |
| مصدران لهما PDF page 1 | كل صفحة وصورة لها file_id/version_id/role، فلا يختلط الموضوع والحل |
| snapshot لا يجمّد JSON الصفحة وPDF | snapshot v2 ينسخ PDF/rasters/page JSON/Markdown/crops مستقلًا عن raw extraction |
| معاينة owner لنسخة منشورة قد تعرض raw تغيّر لاحقًا | المعاينة المعتمدة تقرأ snapshot نفسه، ولا تعيد render/Vision |

## أدوات الوكيل

- `search_library(query, subject?, track?, kind?, year?, session?, exam_type?, document_id?)`: مواضع استدلال وmetadata فقط؛ snippet ليس قراءة كاملة.
- `get_document_metadata(document_id)` ثم `get_table_of_contents(document_id)`.
- `get_lesson_full(node_id)`: درس أصلي موجود، لا درس مختلق. المحتوى الكامل والصور والأسلاف والأبناء والمصادر.
- `list_lesson_parts(node_id)` و`get_lesson_part(part_id)`: أجزاء طويلة ثابتة ومعرّفات مرتبطة بالنسخة. `source_ids` تخص الجزء المقروء، لا الدرس كله.
- `get_section(node_id)`: كتاب أو مرجع، مع الهيكل المحيط. يرفض الامتحان أو سلسلة التمارين ويطلب أداة الحزمة.
- `get_exam_with_solution(node_id)`: الموضوع **كاملًا** + الحل المرفق المطابق إن وجد.
- `get_exercise_collection(node_id)`: السلسلة **كاملة**، والحل المطابق الاختياري.
- `search_within_node`: locator فقط، بلا citation credit؛ يرد بمعرّفات أجزاء مناسبة عندما تكون متاحة.
- `render_answer`: شرح الدرس يتطلب اختيار مصادر قُرئت وأُرسلت فعلًا إلى سياق التشغيل من نشر حالي أو ملف خاص صالح. الصور الأصلية لا تُعرض؛ فحصها داخلي فقط.

لا يقوم LLM بعمليات الملفات أو القص أو Markdown أو تقسيم أجزاء الدرس. قراءة caption لا تعني أن نموذج التدريس فحص بكسلات الصورة. API يتيح raster/JSON؛ الفحص البصري أثناء التدريس والتحقق العلمي ليسا ادعاءً من هذه المرحلة.

### حدود واضحة

`MAX_TOOL_CHARS` و`MAX_CONTEXT_CHARS` حدود بالحروف لا عدّاد tokens دقيق لكل مزود. إذا فاق درس الميزانية، يُرد بخطأ وparts/children. إذا فاقت حزمة امتحان/تمارين الميزانية، يُرد `ATOMIC_BUNDLE_EXCEEDS_TOOL_BUDGET` **دون محتوى جزئي أو credit**؛ زد الميزانيتين بما يناسب سياق نموذجك أو ارفض المهمة بوضوح. لا تقسيم تلقائي إلى أسئلة منفصلة.

cache للمحتوى غير قابل للتغيير، process-local، افتراضيًا 64 ملفًا / 8 MB / 300 ثانية؛ يفحص النشر الحالي والأرشفة قبل lookup. ليس provider prompt caching ولا ذاكرة طالب. إعادة سياق المحادثة الحالية محدودة بآخر عقدتين؛ تحفظ آخر scope/part لكل عقدة لتقليل السياق. تحسين ذاكرة أطول مرحلة منفصلة.

## امتحان + حل، لا مطابقة بالعنوان

1. يرفع المالك الموضوع مع نوعه ومادته وتخصصه وسنته ودورته ونوع الامتحان ومصدره.
2. يرفق PDF الحل **أو** يحدد نطاق حل داخل PDF نفسه؛ نطاقا الموضوع والحل يجب ألا يتداخلا.
3. لكل ملف هوية ومصدر مستقلان. المادة والتخصص إلزاميان؛ كل سنة/دورة/نوع معروف في الموضوع يجب أن يطابق الحل.
4. تأكيد صريح بمراجعة المسائل/الهوية والمصدر، مع دليل نصي لا يقل عن 20 حرفًا. يُسجّل المراجع والتوقيت وبصمة هوية المصدر.
5. التعديل في الهوية/النطاق يُبطل التأكيد؛ النسخة المعتمدة غير قابلة للتعديل. أنشئ نسخة جديدة، ثم راجعها وانشرها.
6. حل مرفق غير مؤكّد يمنع اعتماد النسخة. لا حل مرفق → `solution_status=not_available`، لا اختراع حل رسمي.
7. `official_source` **نسبة قدّمها المالك مع دليل**، وليست شهادة من AI بصحة/رسمية الحل. الحل التعليمي الذي يولده الوكيل تفسير منفصل عن المصدر.

سلسلة التمارين تعامل بحزمة واحدة، لا exercise nodes. المراجع لا تُفرض عليها وحدات أو دروس. الكتب وحدها تحتفظ بالتقسيم الفعلي.

المعالجة تدير **raw PDF كاملًا مرة واحدة** حتى إذا اختيرت نطاقات للنشر، وتلغي IDs المكررة عند وجود الموضوع والحل في الملف نفسه. إعادة الفاشلة/المشكوك فيها تشمل الحالة المطابقة في raw PDF كله؛ لا تعيد صفحات ناجحة. هذا قرار بسيط للتوافق مع Queue الأصلية، وليس وعدًا بتكلفة معالجة الصفحات المحددة وحدها. معاينة الصورة قبل Start لا ترسل Vision.

الصفحات الفاشلة تحفظ الأصل وتبقى بتحذير وعلامة gap صريحة في الحزمة. `extraction_complete=false` عند فقد استخراج صفحة؛ اعتماد المالك لا يجعل النص غير المقروء مقروءًا.

## وصول داخلي فقط

هذه العقود تخص عامل التدريس والمراجعة المصرّح بها للمالك. لا حساب طالب للخدمة ولا service token خارجي ولا MCP adapter عام للمراجع. `/api/library/*` و`/api/agent/*` تتطلب مالكًا؛ الطالب والأستاذ يحصلان على 404 ولو عرفا ID. source IDs والروابط والصور لا تنتقل عبر جواب المحادثة أو SSE أو التصدير. الصور الأصلية تُفحص داخليًا فقط عند الحاجة.

`render_answer` يرفض image blocks والتفاصيل التقنية ومعرّفات/روابط المرجع. حارس إضافي يمنع تطابق 40 كلمة متتابعة من نص مرجع مقروء، حتى مع تغيير علامات الترقيم أو تقسيم blocks. التعريف القصير والمعادلة لا يُمنعان تلقائيًا. هذا منع للنسخ الطويل المباشر، **ليس ضمانًا ضد التسريب بالترجمة أو الترميز أو إعادة الصياغة**؛ اختبارات إساءة الاستعمال وتدقيق مستقل مطلوبان قبل الإطلاق العام.

أصول المالك يجب ألا توضع في public/static/CDN. من يملك الجهاز أو النسخ الاحتياطية يملك البيانات؛ ليست تشفيرًا طرفًا لطرف عن مدير الخادم.

## ترقية بيانات المرحلة الأولى

Migration 002 ذرّية مع backfill primary file metadata. النسخ المعتمدة القديمة وصورها وIDs لا تُكتب من جديد ولا تُسحب من raw extraction. أجزاء legacy تُشتق من **Markdown المعتمد فقط**، مع حدود math/fences/tables. JSON/PDF اللذان لم يُجمّدا في snapshot v1 لا نختلقهما؛ JSON frozen API يرد 404 للقديم. أنشئ نسخة جديدة وأعد المراجعة للحصول على snapshot v2. نجاح صفحات الاستخراج القديمة يُعاد استخدامه دون Vision جديد.

## شرط القراءة والتعافي بعد إعادة المحاولة

الخادم يرفض الشرح بلا `source_ids` مقروءة ومسلّمة فعليًا، بما في ذلك الرد النصي غير المنظّم. تسجيل هوية المصدر أو البحث أو TOC لا يكفي؛ بيانات رفضت بسبب الحجم/السياق لا تمنح credit. عند غياب مرجع مناسب يسأل الوكيل عن الموضوع أو المقطع الناقص بدل الشرح العام من ذاكرته. هذا ليس تحققًا دلاليًا بأن المرجع المختار يثبت كل عبارة؛ يلزم تقييم ملاءمة ووفاء فعلي.

إعادة المحاولة تحتفظ بمواضع المصادر، لا بترخيص دائم: إعادة القراءة تتحقق من النشر/الأرشفة والملف الخاص/انتهاء الصلاحية وتضيف المحتوى الفعلي المحدود إلى السياق. يظهر حدث عام ثابت «مراجعة المعلومات السابقة»، ولا يكشف اسم الكتاب أو أداة أو ID. تبقى المحاولة الفاشلة السابقة مستقلة في المحادثة والتصدير. انظر [تقرير القبول الحالي](acceptance/grounded-teaching-recovery.md).
