# راوتر المراجع — LLM بالفهرس الكامل

## المسار الوحيد

1. يُبنى الفهرس من كل العناوين المنشورة النشطة، مع العلاقات والنوع وصفحات PDF. معرّف الكتاب الاختياري يحصر الفهرس في كتاب منشور ACTIVE.
2. يحدد LLM الأهداف المطلوبة المفقودة من طلب الطالب وسياقه، ويحترم التصحيح والنفي والتغطية السابقة وطلب إعادة الشرح.
3. يختار مرجعًا ضيقًا كافيًا لكل هدف، أو أجزاء مكملة مثل نص التمرين وحله. يمكن اختيار عدة مراجع أو لا شيء. عند الغموض يسأل الطالب ولا يستدعي المدرّس.
4. يزيل الخادم التداخل المثبت ضمن الملف والإصدار نفسيهما، ثم يقرأ النصوص الفعلية دون حفظها في ذاكرة الطالب بعد.
5. يفحص LLM نفسه النصوص المقروءة؛ لا يمكنه اختراع معرّفات أو قراءة مراجع جديدة في هذه المرحلة.
6. يحفظ الخادم ويسلّم المجموعة النهائية فقط. الاستجابة الفاشلة أو المتن الفارغ لا يتحولان إلى ادعاء قراءة.

البرومبتان والعقدان التنفيذيان في `bac/agent/full_index.py`؛ لم تتغير سياستهما في تنظيف الكود. أزيل المسار القديم لترشيح الكلمات والتقييم المستقل بـtrue/false والاحتمالات، وملفات إعداداته ومحللاته. لا قائمة لاختيار استراتيجية قديمة/جديدة ولا حقول حد الثقة أو الفارق.

## الإعداد

من إعدادات المالك اختر **راوتر المراجع — LLM بالفهرس الكامل**:

- Google AI Studio الأصلي: `https://generativelanguage.googleapis.com/v1beta`، قالب `gemini-3.5-flash-lite`.
- OpenAI-compatible: OpenAI أو Vercel أو OpenRouter أو Custom. لا يُثبت نوع النموذج بمجرد نجاح اتصال `/models`؛ يجب أن يدعم استدعاء الدوال ويُختبر على مراجعك.
- مثال Sol: مزوّد Custom، بروتوكول OpenAI-compatible، رابط `https://ohhmyagent.com/v1`، اسم `gpt-6-sol` حسب كتالوج المزوّد.
- Anthropic الأصلي باقٍ للتدريس والاستخراج، وليس نقلًا مدعومًا في الراوتر الحالي.
- سقف المصادر الافتراضي 3، ويمكن ضبطه 1–8. الأهداف التي تتجاوز السقف تحتاج رفعه أو تضييق الطلب.
- حفظ الإعداد لا يرسل طلب توليد. الراوتر يحتاج إعدادًا ومفتاحًا وحالة تفعيل صريحة؛ لا ينشئ التحديث حساب مزوّد أو مفتاحًا تلقائيًا.

اتساع السياق لا يلغي الحصة أو حدود الرموز في الدقيقة. الفحص بعد القراءة يضيف طلبًا ثانيًا عندما توجد مراجع، وقد يزيد التكلفة والزمن. الأسعار غير المعروفة والرموز غير المبلّغة ليست صفرًا.

## الإعدادات القديمة والمفاتيح

- إعداد LLM محفوظ عبر OpenAI-compatible أو Google الأصلي: يبقى المزوّد والمفتاح والتفعيل كما هي، لكن تنفذ النسخة الجديدة مسار الفهرس والفحص وحده. الحقول المتقاعدة تُحجب من الواجهة وحفظ إعداد جديد لا يعيدها.
- إعداد يستخدم بروتوكولًا متقاعدًا/غير مدعوم: لا يُعاد تشغيله ولا يُعاد توجيه مفتاحه إلى مزوّد LLM. تعرض الواجهة طلب إعادة الإعداد؛ التشغيل والاتصال به متوقفان قبل أي طلب شبكة.
- يجب اختيار مزوّد مدعوم وإدخال مفتاحه صراحةً. تبديل الرابط أو البروتوكول بلا مفتاح جديد مرفوض.
- صفوف الإعدادات القديمة والمفاتيح المشفرة ولقطات المحادثات باقية في البيانات للرجوع والتدقيق، لا كمسار تنفيذي متاح. لم نضف migration لتغييرها أو حذفها.
- التشغيلات القديمة المصوّرة على بروتوكول غير مدعوم تفشل بوضوح، ولا تنتقل سرًا إلى نموذج آخر.

## ما لم يُحذف

الكتاب وPDF الأصلي والنصوص المستخرجة والرسوم والحسابات والمحادثات ووحدات Docker لم تُمس. جداول الإعدادات وmigrations السابقة محفوظة لأن حذفها يكسر التهيئة واستعادة قواعد البيانات القديمة. أدلة الاختبارات التاريخية تحت `docs/acceptance/` ليست إعدادات تشغيل حالية.

## تحديث Docker بأمان

خذ backup من البيانات ومفاتيح التشفير قبل التحديث. حدّث المشروع من GitHub ثم أعد بناء API وworker باستعمال ملفات Compose المستخدمة فعلًا، بما فيها override الكتاب إن وجد، ونفس وحدات البيانات. حدّث واجهة المتصفح بعدها.

لا تستخدم `docker compose down -v`، ولا تشغّل API وworker بإصدارين مختلفين، ولا تستبدل ملفات النشر المحلية دون مراجعة. رفع GitHub لا يثبت التحديث في Docker المستخدم تلقائيًا.
