# اختيار المراجع المستقل وإعداد المزوّدين

## الحالة

هذه بنية **تجريبية اختيارية** وليست شهادة جاهزية للعربية/الدارجة. القالب الجديد غير المحفوظ يختار Google AI Studio مع `gemma-4-31b-it` كراوتر، مستقلًا عن نموذج التدريس ونموذج الاستخراج. الإعدادات المحفوظة سابقًا لا تُبدّل تلقائيًا. حفظ الإعداد لا ينفّذ توليدًا ولا يفعّل المنسق ضمنيًا. اقرأ [مسار Gemma](GEMMA_ROUTER.md) و[تقرير فحصه](acceptance/gemma-router.md) قبل التفعيل.

**تاريخ LAYA، وليس نتيجة Gemma:** اختُصرت سياسة LAYA إلى 1529 حرفًا. قَبِل طلب المقارنة العربي بـHTTP200، واختار المرجعين المطلوبين لكنه أضاف مرجع شحن المكثفة غير المطلوب. الطلبات السابقة بالسياسة الطويلة كانت تُرفض بـHTTP422 لسبب غير مثبت. لم تُخفّض حدود قبول LAYA؛ بقي مساره للتبديل اليدوي. راجع [فحص التحديث المتعدد](acceptance/multi-label-selector.md). مسار Gemma الجديد يستخدم قرارات boolean صريحة وسياسة مستقلة، لا احتمالات LAYA.

## الإعداد من حساب المالك

إعدادات الحساب ← إعداد النماذج ← الاستخدام:

- وكيل التدريس.
- استخراج الكتب.
- راوتر اختيار المراجع — Gemma / LAYA.

قوالب OpenAI، Google AI Studio، Anthropic/Claude، Vercel AI Gateway، OpenRouter وCustom تضبط الرابط والبروتوكول والنموذج المقترح. أدخل المفتاح فقط، ويمكنك تغيير النموذج. **القالب ليس وعدًا بأن النموذج متاح في حسابك أو يدعم الرؤية والأدوات.** اختبار الاتصال المحفوظ يجلب قائمة النماذج فقط؛ لا يختبر توليدًا أو Vision أو دقة اختيار.

Anthropic يستخدم `/messages` و`x-api-key` ونسخة بروتوكول Anthropic، وليس محاكاة OpenAI. Google **في خانة الراوتر** يستخدم البروتوكول الأصلي `/v1beta/models/{model}:generateContent` و`x-goog-api-key`، مع System Instruction ونداء إخراج `choose_sources`. Google في التدريس/الاستخراج يبقى OpenAI-compatible كما كان. تُطبّع بادئة `models/` داخليًا. حقول المفاتيح لا تُملأ بعد الحفظ، وتُمسح عند تبديل المزوّد/البروتوكول/الاستخدام. السيرفر يرفض إعادة توجيه المفتاح المحفوظ إلى عنوان أو بروتوكول مختلف بلا مفتاح جديد.

قالب Vercel في خانة القرار يستخدم:

- Base URL: `https://ai-gateway.vercel.sh/v1`
- Model: `convaiinnovations/laya`
- Protocol: **Typed Evaluation**؛ الطلب إلى `/evaluate`، وليس `/chat/completions`.

مسار Google/Gemma يعيد خريطة `selected` من true/false لكل alias؛ لا يختلق احتمالات ولا يطبّق حدود الثقة الرقمية الخاصة بـLAYA. يمكن أيضًا استخدام قرار OpenAI/Claude/OpenRouter: هذه المسارات السابقة تعيد `relevance` رقمية مستقلة لكل alias. كل المسارات طلب قرار واحد، وليست Agent ينفّذ أدوات. لتشغيل نموذج Chat كقرار عبر Vercel اختَر Custom مع رابط Vercel وبروتوكول OpenAI-compatible. تقديرات الاحتمالات ليست ثقة معايرة أو برهان صحة.

فعّل checkbox اختيار المراجع فقط بعد اختبارات قبولك. **حتى ثلاثة مراجع افتراضيًا**؛ يمكن ضبط سقف 1–8. قرار واحد يستطيع اختيار صفر أو واحد أو عدة مراجع معًا. لا fallback أو إعادة محاولات مدفوعة خفية عند 429 أو فشل البروتوكول.

## البرومبت والاختيار المتعدد

**Gemma:** `config/gemma_router.yaml` يحتوي النسخة المختصرة الأخيرة التي أرسلها المالك. تُرسل مرة واحدة في `systemInstruction` مع غلاف ثابت يفصل البيانات غير الموثوقة عن السياسة، ويفرض قرارًا لكل مرشح. الطلب والسياق وmetadata تُرسل JSON في محتوى المستخدم. يُختار المرجع الكافي لكل مفهوم مطلوب، وليس مرجعًا واحدًا لكل الرسالة. العقد يقبل عدة true أو كلها false. راجع [تفاصيل المسار والبرومبت](GEMMA_ROUTER.md).

**LAYA والمسارات السابقة:** الفقرات التالية تصف آلية Typed Evaluation التاريخية، ولا تصف النقل الأصلي لـGemma.

`config/selector.yaml`، الإصدار3، يحتوي الصيغة المختصرة المصرّح بها من المالك: العربية والدارجة واللغات المختلطة، القصد المصحح، النفي، السياق، المقارنات، والتحديد دون التخمين. انخفضت السياسة من3960 إلى1529 حرفًا، وتُرسل النسخة التنفيذية كاملة **مرة واحدة داخل `state.selection_policy`** دون قص صامت. أسئلة `boolean` قصيرة تربط كل مرشح بالسياسة في الحالة المشتركة؛ ذلك يمنع إعادة السياسة في كل رأس. حفظنا النسخة الطويلة في أدلة الاختبار، لا بوصفها السياسة التنفيذية الحالية.

في الطلب Native تُسلسل الحالة كاملة إلى نص JSON؛ لا تُرسل `criteria` الاختيارية لأن قواعد التضمين والاستبعاد موجودة في السياسة نفسها. تغيير صيغة النقل لم يحل HTTP422 بالسياسة الطويلة. الصيغة المختصرة قُبلت في فحص حي واحد؛ لا يثبت ذلك أن رفض الطلبات السابقة كان بسبب الحجم وحده أو أن جميع الطلبات اللاحقة ستُقبل.

الحالة تتضمن الطلب الحرفي وmetadata المرشحين والاختيارات السابقة في التشغيل نفسه، دون هويات أو مفاتيح أو نصوص الدروس. كل alias له احتمال تضمين مستقل. الإجابات كلها false تعني قائمة فارغة، فلا نحتاج مرجعًا وهميًا باسم `none`.
الواجهة قد تقص النص داخليًا وفق نافذة النموذج، ولا ندعي معرفة ما قرأه المشفّر أو ضمان التزامه بالسياسة. يلزم اختبار حي على بياناتك؛ دعم عدة أسئلة boolean لا يثبت فهم الدارجة.

كتالوج Vercel للنموذج المستخدم يعلن نافذة **8192 توكن**. ميزانية الإدخال تخص السياسة والطلب والسياق وmetadata وأسئلة القرار، وليس نص السياسة وحده. لا تُرسل إليه الدروس الكاملة؛ يقرأها نموذج التدريس بعد الاختيار. قياس الحروف/UTF-8 ليس عدّ توكنات، ولا نستنتج أن HTTP422 الحالي سببه تجاوز 8K. لا نفترض أن تغيير `max_len` في المكتبة المحلية يغيّر إعداد Vercel المستضاف.

## التنفيذ

1. التحية القصيرة لا تستدعي نموذج القرار. السؤال التعليمي يُركّز على جزء حرفي من طلب الطالب؛ في الدارجة يمكن أخذ الجزء بعد «نفهم». لا نطلب من نموذج آخر اختراع بحث.
2. backend يرشّح حتى 10 نتائج من أول 2000 عقدة حالية منشورة معتمدة. هذه **مطابقة كلمات عنوان/مادة/keywords** وليست بحثًا دلاليًا/هجينًا. مرجع موجود بلا كلمات عنوان مناسبة قد لا يظهر. يوجد استبعاد ضيق لعنوان حركة شاقولية صريح عندما يطلب السؤال حركة غير شاقولية؛ ليس هذا مدققًا دلاليًا عامًا.
3. نموذج القرار يرى السؤال وبيانات المرشحين فقط: العنوان، النوع، المادة، الشعبة، مدى الصفحات، ووصف/ملخص metadata إن كان موجودًا. لا يرى محتوى الدروس أو الملاحظات أو هوية الطالب أو معرّفات الملفات الحقيقية. أسماء المرشحين والتحديدات داخلية، لا تظهر للطالب.
4. Google/Gemma يُلزَم بنداء واحد `choose_sources` بخريطة boolean كاملة، ويُرفض الكلام الإضافي والنداء الزائد والمفاتيح الناقصة أو الغريبة والإجابة المبتورة. لا احتمالات مصطنعة. LAYA `/evaluate` يستقبل سؤال boolean لكل مرشح، ويتحقق من الاحتمال المحدود والمنتهي؛ حد الثقة 0.55 والفارق 0.10 ثابتان. الفارق يخص التضمين والاستبعاد **لنفس المرجع**، لا مرجعين مختلفين. **أي من العقدين لا يضمن الصحة الدلالية.**
5. تُختار المراجع حتى السقف: بترتيب الترشيح في Google/Gemma؛ وباحتمال الملاءمة ثم ترتيب الترشيح عند التعادل في المسارات الرقمية. السقف الافتراضي ثلاثة، لذا قد يُستبعد مفهوم رابع مطلوب إذا لم يرفعه المالك. لا تكرار لمعرّف أو حلقات اختيار مصدر وراء آخر. طلب `essential_context` لاحق لا يعيد مرجعًا قرأه التشغيل نفسه. **لا قراءة كاملة قبل انتهاء قرار الاختيار المتعدد.**
6. بعدها يقرأ backend كل مصدر كامل فعليًا، دون رصيد قراءة جزئي إذا فشل أحدها أو تجاوز المجموع حد السياق. تُرفض العقد التي لا تحتوي إلا على عناوين وتعليقات provenance؛ هذا فحص كفاية بنيوية لا مدقق صحة دلالية. الامتحان/مجموعة التمارين يُحمّلان كحزمة كاملة وحل مطابق إن وجد. تُراجع النسخة المعتمدة بعد انتظار الشبكة. metadata لا تمنح اعتماد قراءة.
7. السياق الخاص الكامل يصل إلى أول طلب لنموذج التدريس. لا تعرض أدوات البحث/التصفح العشر لهذا النموذج في الوضع المنسّق. تبقى أدوات الحساب والتحقق والرسم والملفات الخاصة والملاحظات، مع شروط صلاحياتها.
8. إضافة سياق من نموذج التدريس مسموحة **مرة واحدة** فقط وبطلب `essential_context` ذي أهمية essential وسبب محدد. يختار المنسق، ولا يمرّر النموذج معرّفًا من اختراعه. يجب استلام القراءة في جولة لاحقة قبل الرد؛ render مع طلب قراءة في الدفعة نفسها مرفوض.
9. نموذج التدريس له 4 طلبات افتراضيًا (2–8 قابلة للضبط)، آخرها محجوز للرد المنظم فقط. لا loop بحث مفتوح، ولا تمديد للمهلة أو تغيير مزود تلقائي. الحساب ثم التحقق منه تبعيتان؛ لا ندعي تشغيل أدوات تعتمد إحداها على الأخرى بالتوازي.
10. إذا لم يوجد مرجع معتمد بالفعل، تبقى بوابة الشرح المسند: سؤال توضيح قصير/رفض صريح بدل شرح من الذاكرة. القراءة الفعلية لا تثبت أن كل الشرح مستنتج دلاليًا من المصدر الصحيح.

## حجم السياق

قراءة المنسق الكاملة تتجاوز سقف نتيجة الأداة القديم 22k حرف. يمكن ضبط `max_context_chars` لنموذج التدريس من 10k إلى 4M **حرف، وليس توكنًا**؛ الافتراضي يبقى إعداد الخادم. لا حذف صامت لنهاية المصدر ولا تلخيص مدّعى على أنه قراءة كاملة. عند تجاوز الحد يفشل التشغيل بوضوح. حد السياق الحقيقي للمزوّد وأرصدة الحساب ومدة التشغيل ما زالت تطبّق؛ لا يعني الحقل سعة فعلية للموديل. أدوات الصور لها حدودها المنفصلة، وصور الكتب لا تُعرض للطالب.

## الخصوصية والتشغيل

- إعداد القرار مستقل ومشفّر، ويُلتقط مع إعداد التدريس عند enqueue؛ تغييره لا يغيّر تشغيلًا قيد العمل.
- لا قائمة مكتبة أو أسماء مصادر أو صور أصلية أو أسماء أدوات في المحادثة/SSE/exports. يبقى درج ملخص مراحل لكل جواب، لا سلسلة التفكير الداخلي.
- استخدام القرار يُسجّل تحت `source_selection` بما يبلغه المزوّد؛ البيانات المفقودة غير متاحة وليست صفرًا. `status=ok` يعني استجابة سليمة العقد، لا نجاحًا في اختيار المرجع الصحيح. لا نسمي أسعار كتالوج المزوّد فاتورة أو ضمان حصة مجانية.
- سياسة منع نسخ نص المراجع وسرية الطرق السابقة تبقى كما هي؛ الفلتر ليس إثباتًا رياضيًا ضد كل تسريب دلالي.
- في الوضع القديم، قبل تفعيل إعداد القرار، تبقى السياسة السابقة دون سقف ثابت للجولات. لا ندعي أن تثبيت التحديث وحده يفعّل مسار القرار.

## Docker / migrations

ابدأ بنسخة staging؛ تحقق Gemma على كتابك الحقيقي ما زال مطلوبًا. مسار Gemma لا يضيف migration، لكن تحديث المستودع يضم migration008 السابقة للاختيار المتعدد إن لم تُطبّق. أوقف API وworker وخذ backup كاملًا من قاعدة البيانات **ومفاتيح التشفير** والملفات. احفظه خارج البيانات بمجلد خاص وفق [دليل التشغيل](OPERATIONS.md). من نسخة المستودع على فرع `main`، تحقق من تعديلاتك المحلية ثم حدّث؛ توقف عند أي تعارض ولا تستبدل ملفاتك بالقوة:

```bash
git status --short
git pull --ff-only
docker compose up -d --build api worker
docker compose ps
```

تضيف migration007 جداول القرار ولقطته؛ migration008 تنشئ نسخة من إعداد القرار النشط إذا كان سقفه القديم واحدًا وترفعه إلى ثلاثة. تبقي الصف القديم ولقطات التشغيلات ومفتاحه المشفّر دون تعديل، وتحافظ على حالة التفعيل: **لا تفعّل محدِّدًا معطّلًا**. السقوف الأكبر من واحد وإعدادات التدريس/الاستخراج لا تتغير.
API وworker يجب أن يعملا من النسخة نفسها وبنفس volume ومشروع Compose. لا `down -v`. الرجوع إلى كود أقدم يحتاج استعادة backup كاملًا مع الكود الموافق؛ لا تشغيل القديم على DB رُقّيت. حدّث صفحة المتصفح. اختبارنا لم يغيّر Docker الخاص بك. لا مفاتيح في Git/توثيق/لقطات اختبار.
