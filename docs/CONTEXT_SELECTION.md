# راوتر المراجع — LLM بالفهرس الكامل

## المسار الوحيد

1. يجهز الخادم السؤال الحالي والسياق الحديث والشعبة والمادة والمرفقات المتاحة فعلًا. التحيات/الشكر والمساعدة المحددة بقائمة الخادم المغلقة يمكن أن تنتهي حتميًا دون طلب مزوّد.
2. يقيّم النموذج الأساسي كفاية **الأجسام المحمّلة فعلًا** باستدعاء `assess_context` معزول؛ لا يُرسل الفهرس إلى هذا الاستدعاء. إذا كانت كافية يعيد استخدامها دون راوتر، في الرسالة الثانية أو رقم N.
3. عند نقص المرجع أو عدم التأكد يُبنى كتالوج كامل من المصادر المنشورة النشطة في شعبة الطالب ومادة المحادثة: العناوين و`summary` و`covers` وحجم النص؛ لا أجسام الدروس. لا تقليص للفهرس أو مكتبة الدروس لحل التكلفة.
4. يحدد الراوتر أهداف الطالب ويختار مرجعًا ضيقًا لكل هدف أو أجزاء مكملة. يراعي المراجع السابقة والمهمة غير المنتهية والتصحيح والنفي؛ التمرين/الاختبار مع حله يبقى حزمة منطقية.
5. يتحقق الخادم من معرّفات المصادر وصلاحياتها وإصدارها، ويزيل التداخل المثبت ثم يقرأ النص الفعلي. لا حد أحرف تطبيق قديم من نوع 60 ألف؛ حدود المزوّد والحصة والتنفيذ باقية.
6. يعاد تقييم كفاية الأجسام بواسطة النموذج الأساسي قبل الشرح. **لا استدعاء تحقق دلالي ثانٍ يرسل أجسامها للراوتر**. البيانات الوصفية والقراءة البنيوية ليست ضمان صحة أو كفاية دلالية.
7. ينتهي توضيح الراوتر دون تشغيل جولات الشرح. السؤال الفارغ/غير الآمن في قرار `clarify` يستبدل بسؤال خادم محدود، ثم يعاد التحقق من القرار كاملًا؛ لا قراءة ولا استدعاء راوتر إضافي. معرّف مختلق أو قرار `read` غير صالح يظل مرفوضًا.

### عقد الأدلة وحدود المحاولات

العقد الحي يحتوي `requirements` بأربع مجموعات: `goals` و`rules` و`conditions` و`prerequisites`. كل عنصر يحمل `id` و`description` و`supports`، وكل دعم زوج `source_id`/`evidence_id` من علامات المقاطع التي أنشأها الخادم. لا قائمة روابط مكررة منفصلة.

يحوّل الخادم هذه الأزواج إلى عقد التغطية الداخلي السابق، ويستخرج الاقتباس من النص الأصلي بنفسه؛ لا اختلاق دعم ولا تصحيح تقريبي لمعرفات الأدلة. تبقى الاستدعاءات/السجلات القديمة مقبولة بعقدها السابق وتخضع لنفس ضوابط الكفاية. الدعم الفارغ أو الفجوة الحقيقية لا يصبح `sufficient`.

إغفال ربط هدف في العقد القديم قابل **لمحاولة إصلاح صياغة واحدة**، وليس تجاوزًا للتحقق. الشروط والاعتماديات غير المدعومة تبقى فجوات حقيقية. الحد السابق ثلاث محاولات تقييم لكل تشغيل باقٍ، بما فيها الإصلاح؛ لا محاولة رابعة. الراوتر العادي مرة، وطلب `essential_context` الضروري يمكنه إضافة تنسيق واحد وفق الحدود السابقة، وليس حلقة إعادة بحث.

عقد `render_answer` مشتق من `PresentedAnswer`. توافق Google يسطّح اتحاد أنواع الكتل فقط، ولا يحذف `checked_claims` أو `history_evidence` أو حالة `history_summary`. التحقق الصارم من نوع الكتلة والنتيجة والمصدر والدليل يبقى على الخادم.

مراجعة الحوار خالية من تعديل ملاحظات التعلم، مع حظر تنفيذي أيضًا. ملخص حوار خالص يستخدم `history_summary`، أما الملخص مع تعليم جديد فيستخدم `teaching` وأدلة الطالب الفعلية وأدلة المراجع معًا. لا تُعد أمثلة الكتاب سجلًا لأخطاء الطالب.

العقد النشط في `bac/agent/full_index.py`. بيانات المالك مدخلات غير موثوقة، وليست أوامر. المصادر التاريخية بلا ملخصات تستخدم ما يتوفر من العناوين فقط؛ للحصول على الفهرس الجديد أعد رفع Markdown بمعلومات القسم.

## الإعداد

من إعدادات المالك اختر **راوتر المراجع — LLM بالفهرس الكامل**:

- Google AI Studio الأصلي: `https://generativelanguage.googleapis.com/v1beta`، قالب `gemini-3.5-flash-lite`.
- OpenAI-compatible: OpenAI أو Vercel أو OpenRouter أو Custom. لا يُثبت نوع النموذج بمجرد نجاح اتصال `/models`؛ يجب أن يدعم استدعاء الدوال ويُختبر على مراجعك.
- مثال Sol: مزوّد Custom، بروتوكول OpenAI-compatible، رابط `https://ohhmyagent.com/v1`، اسم `gpt-6-sol` حسب كتالوج المزوّد.
- Anthropic الأصلي باقٍ للتدريس فقط، وليس نقلًا مدعومًا في الراوتر الحالي.
- سقف المصادر الافتراضي 3، ويمكن ضبطه 1–8. الأهداف التي تتجاوز السقف تحتاج رفعه أو تضييق الطلب.
- حفظ الإعداد لا يرسل طلب توليد. الراوتر يحتاج إعدادًا ومفتاحًا وحالة تفعيل صريحة؛ لا ينشئ التحديث حساب مزوّد أو مفتاحًا تلقائيًا.

اتساع السياق لا يلغي الحصة أو حدود الرموز في الدقيقة. لا طلب تحقق دلالي ثانٍ بعد القراءة؛ استيراد ومراجعة ونشر Markdown لا يرسلون طلبات توليد. الأسعار غير المعروفة والرموز غير المبلّغة ليست صفرًا.

## الإعدادات القديمة والمفاتيح

- إعداد LLM محفوظ عبر OpenAI-compatible أو Google الأصلي: يبقى المزوّد والمفتاح والتفعيل كما هي، لكن تنفذ النسخة الجديدة مسار الكتالوج والاختيار فقط. الحقول المتقاعدة تُحجب من الواجهة وحفظ إعداد جديد لا يعيدها.
- إعداد يستخدم بروتوكولًا متقاعدًا/غير مدعوم: لا يُعاد تشغيله ولا يُعاد توجيه مفتاحه إلى مزوّد LLM. تعرض الواجهة طلب إعادة الإعداد؛ التشغيل والاتصال به متوقفان قبل أي طلب شبكة.
- يجب اختيار مزوّد مدعوم وإدخال مفتاحه صراحةً. تبديل الرابط أو البروتوكول بلا مفتاح جديد مرفوض.
- صفوف الإعدادات القديمة والمفاتيح المشفرة ولقطات المحادثات باقية في البيانات للرجوع والتدقيق، لا كمسار تنفيذي متاح. migration010 يزيل تفعيل خانة الاستخراج، ولا يحذف إعدادات الراوتر أو التدريس أو المفاتيح التاريخية.
- التشغيلات القديمة المصوّرة على بروتوكول غير مدعوم تفشل بوضوح، ولا تنتقل سرًا إلى نموذج آخر.

## ما لم يُحذف

لا حذف تلقائيًا للكتب واللقطات والحسابات والمحادثات ووحدات Docker. يستطيع المالك حذف محتوى المكتبة صراحةً بالنطاق المحدد؛ ملفات الاستخراج الخام التاريخية والنسخ الاحتياطية الخارجية لا يحذفها المسار الجديد. جداول الإعدادات وmigrations السابقة محفوظة لأن حذفها يكسر التهيئة واستعادة قواعد البيانات القديمة. أدلة الاختبارات التاريخية تحت `docs/acceptance/` ليست إعدادات تشغيل حالية.

## تحديث Docker بأمان

خذ backup من البيانات ومفاتيح التشفير قبل التحديث. حدّث المشروع من GitHub ثم أعد بناء API وworker باستعمال ملفات Compose المستخدمة فعلًا، بما فيها override الكتاب إن وجد، ونفس وحدات البيانات. حدّث واجهة المتصفح بعدها.

لا تستخدم `docker compose down -v`، ولا تشغّل API وworker بإصدارين مختلفين، ولا تستبدل ملفات النشر المحلية دون مراجعة. رفع GitHub لا يثبت التحديث في Docker المستخدم تلقائيًا.
