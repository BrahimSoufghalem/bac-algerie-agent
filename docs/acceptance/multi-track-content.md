# محتوى واحد لعدة شعب

## ما تغير

- خيار الشعب المستهدفة أصبح checkboxes متعددة في رفع المصدر ومحرر هوية المسودة وبيانات الحل. لا نسخ مستند جديد لكل شعبة.
- تحفظ قائمة tracks في metadata ويظل track القديم أول قيمة للتوافق. لا migration جديدة ولا إعادة كتابة للكتاب أو الحسابات القديمة.
- المادة محدودة بالخيارات المتاحة لجميع الشعب المحددة. يمنع الخادم القوائم الفارغة، الشعب غير المعروفة والمادة غير المتوافقة؛ التكرار والأسماء القديمة المعروفة تُطبع إلى IDs محددة.
- فهرس الراوتر والبحث والقراءة يستخدمان عضوية الطالب في قائمة المصدر، مع قيد مادة المحادثة نفسه. شعبة الطالب ما تزال اختيارًا واحدًا ثابتًا.
- الحل المرفق في رفع مزدوج يرث كل شعب الموضوع. التحقق يتطلب نفس مجموعة الشعب، مهما كان ترتيبها، ولا تكفي مطابقة أول شعبة فقط.
- الكتاب المنشور سابقًا يُعدّل عبر إنشاء نسخة جديدة وتعديل هوية المسودة ثم المراجعة والنشر، باستخدام الاستخراج المكتمل نفسه. المسودة لا توسع وصول الطلاب قبل نشرها؛ حذف شعبة عند النشر يمنع قراءتها لاحقًا.
- المصادر القديمة بلا tracks تستعمل شعبة track السابقة، دون توسيع الجمهور تلقائيًا.

## التحقق المحلي

- 283 اختبار Python ناجحًا، بما فيها 9 حالات جديدة خاصة بالمحتوى متعدد الشعب.
- 25 اختبار Chromium ناجحًا للمجموعة كاملة، بينها الرفع متعدد الشعب، تقاطع المواد وتعديل المسودة، مع فحص العرض على الهاتف والحاسوب.
- TypeScript/Vite build ناجح؛ Ruff F بالأمر نفسه المستخدم في CI ناجح.
- جرى التحقق من أن شُعبتين تريان نفس المستند والدرس، وأن شعبة غير مستهدفة ومادة أخرى لا تصلان إليه، وأن عدد المستندات وPDF الخام يبقى واحدًا.
- اختبار تعديل كتاب منشور وإضافة ثم حذف شعبة نجح دون أي قراءة نموذج جديدة أو إعادة استخراج.
- لا استدعاءات LLM/OCR خارجية أو مدفوعة. هذه اختبارات عقد وعزل وواجهة، وليست قياس دقة جديدًا للنماذج.
- التحذيران المعتادان: تقادم Starlette/httpx وZIP مكرر عمدًا في اختبار فساد الاستعادة.

نجاح الاختبارات محلي، ولا يثبت اكتمال GitHub Actions أو تثبيت التحديث في Docker المستخدم.
