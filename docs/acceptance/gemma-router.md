# فحص راوتر Gemma 4 — المحاولة المعادة

## التنفيذ

النموذج `gemma-4-31b-it` عبر Google AI Studio native في دور اختيار المراجع فقط. نموذج التدريس والاستخراج لم يتغيرا. السياسة المختصرة في `config/gemma_router.yaml` مع غلاف `systemInstruction` ثابت، وقرار boolean لكل مرشح. لا احتمالات ثقة مختلقة، ولا fallback أو إعادة طلب خفية.

## النتيجة الفعلية

أعاد المالك طلب مجموعة24 صراحةً بعد توقف المحاولة الأولى عند HTTP503.

- المخطط: **24**؛ المحاوَل في المحاولة الجديدة: **24**.
- قرارات صحيحة تمامًا: **15**.
- قرارات خاطئة تمامًا/جزئيًا: **0**.
- حالات بلا جواب صالح بسبب المزوّد/العقد: **9**.
- لم تُجرّب: **0**.
- أخطاء الخدمة: `{"HTTP_500": 8, "NETWORK_OR_TIMEOUT": 1}`.

كل سؤال أُرسل مرة واحدة في هذه المحاولة. بعد أول أربعة أجوبة صحيحة ظهرت ثلاثة HTTP500 متتالية؛ توقفنا ثم أكملنا **الحالات غير المجربة فقط** بعد تهدئة الخدمة. حدث توقف آخر عند مهلة شبكة في الحالة12 ثم استؤنفت الحالات13–24 فقط؛ لم تُزَد المهلة ولم يُكرر السؤال. الجميع ضمن سقف24 طلبًا. لا نموذج أو برومبت تغير، ولم تُخفّض حدود LAYA أو تُحوّل booleans إلى احتمالات.

الصحة هنا تطابق مجموعة المراجع المطلوبة تمامًا: المرجع الزائد أو الناقص خطأ. أعطال API ليست أخطاء اختيار دلالية ولا تُحسب نجاحًا. النسبة المشروطة بالأجوبة الصالحة، إن ذُكرت، مقامها 15 وليس24؛ لا تمثل ضمان موثوقية الخدمة أو دقة عامة.

## الفحص المحلي والنشر

- pytest: **323** ناجح، منها **19** تحققًا خاصًا بالبروتوكول الأصلي.
- Playwright: **22** ناجح.
- TypeScript/Vite build وRuff `--select F`: ناجحان محليًا.
- لا ندعي نجاح GitHub Actions أو بناء Docker دون تحقق منفصل من تشغيل CI.
- تحديث GitHub يضم دعم الاختيار المتعدد السابق، بما فيه migration008 إن لم تُطبّق. يحفظ حالة التفعيل والمفتاح واللقطات؛ لا يبدّل LAYA المحفوظ إلى Google تلقائيًا.
- للتحديث: backup كامل للبيانات ومفاتيحها، `git pull --ff-only`، ثم إعادة بناء API وworker معًا. لا `down -v`. أدخل مفتاح AI Studio وفعّل الراوتر صراحةً في staging.
