# تنظيف الراوتر: LLM فقط

## النتيجة

أصبح راوتر المراجع يستخدم مسار LLM واحدًا: الفهرس المنشور الكامل → تحديد الأهداف → قراءة المصادر → فحص النصوص → التسليم. أزيلت استراتيجية المرشحين بالكلمات والتصنيف true/false واحتمالات التضمين وحد الثقة والفارق. إزالة التصنيف لا تعني إلغاء نداءات الدوال المنظمة: يستخدم LLM عقدي `route_sections` و`verify_sections` لتحديد الأقسام والنتيجة بأمان، لا نموذج Typed Evaluation.

التدريس واستخراج الكتب باقيا على إعداداتهما. لا حذف للكتاب أو الملفات المستخرجة أو الحسابات أو المحادثات أو وحدات Docker.

## التنظيف الفعلي

حُذفت 8 ملفات من المستودع:

- `bac/agent/selection.py`
- `bac/agent/google_selector.py`
- `config/selector.yaml`
- `config/gemma_router.yaml`
- `tests/test_context_selector.py`
- `tests/test_google_selector.py`
- `tests/test_multi_label_selection.py`
- `docs/GEMMA_ROUTER.md`

استُبدلت اختبارات المسار المتقاعد باختبارات الراوتر الحالي وحماية الإعدادات المحفوظة. أزيل من الواجهة بروتوكول Typed Evaluation، وقائمة الاستراتيجيتين، والقوالب التي كانت تختار نموذج التصنيف افتراضيًا. الراوتر يدعم OpenAI-compatible وGoogle الأصلي؛ قالب Google الآن `gemini-3.5-flash-lite`، والمزوّد Custom يقبل LLM مثل Sol.

Anthropic الأصلي باقٍ للتدريس والاستخراج، ولا يُعرض ضمن مزودي الراوتر غير المدعومين حاليًا. ترشيح نوع `evaluation` خارج قائمة نماذج الراوتر هو منع إظهار نماذج التصنيف، وليس إعادة توفير المسار المحذوف.

## توافق الإعدادات وحماية المفاتيح

- إعداد LLM محفوظ ومتوافق: يبقى مزوّده ومفتاحه وحالة تفعيله؛ يستخدم الإصدار الجديد الفهرس الكامل دون قائمة لاختيار المسار القديم.
- إعداد على بروتوكول متقاعد/غير مدعوم: يرفض التشغيل والاتصال قبل أي طلب شبكة. تعرض الواجهة طلب إعادة الإعداد بمزوّد LLM ومفتاحه الجديد، ولا تنقل المفتاح السابق تلقائيًا.
- الحقول المتقاعدة تُحجب من إعدادات API العامة وتُرفض في إعدادات جديدة. حفظ إعداد LLM متوافق دون مفتاح جديد يحافظ على مفتاحه الصحيح.
- عند تغيير المزوّد أو البروتوكول، يظل شرط مفتاح جديد قائمًا.
- صفوف الإعدادات القديمة المشفرة ولقطات التشغيل والمحادثات باقية في قاعدة البيانات للتدقيق والاستعادة؛ ليست طرق تنفيذ متاحة. لا migration جديدة لحذفها أو إعادة كتابة مفاتيحها.
- migrations القديمة وأدلة الاختبارات التاريخية محفوظة؛ حذف migrations يكسر تهيئة/استعادة البيانات. التقارير السابقة ليست توثيق الإعداد الجاري، وقد تشير إلى ملفات حُذفت من النسخة الحالية وتظل موجودة في التزاماتها التاريخية.

## التحقق المحلي

- **264 اختبار Python ناجحًا** للمجموعة الحالية كاملة.
- **Ruff F: ناجح** على الوحدات والتجارب والاختبارات.
- **TypeScript + Vite build: ناجح**.
- **اختبار واجهة مزوّدي النماذج: ناجح** على Chromium محلي، بما يشمل القالب الجديد، غياب خيارات التصنيف، حفظ فصل الأدوار ومسح حقل المفتاح عند التبديل، العرض الضيق، وعدم إرسال توليد ضمن تغيير الخيارات.
- اختبارا التحذير في Python هما تقادم Starlette/httpx وملف ZIP مكرر عمدًا في اختبار فساد الاستعادة.
- لم تُجرَ أي استدعاءات توليد خارجية جديدة أو إعادة تقييم مدفوعة للأسئلة الـ24 أو الـ8 في مهمة التنظيف. لا نعلن نتيجة دقة جديدة بسبب حذف الكود.
- نجاح الاختبارات محلي؛ لا يثبت نشر Docker المستخدم أو اكتمال GitHub Actions.

## التطبيق بعد التحديث

حدّث المشروع من GitHub وأعد بناء API وworker مع نفس ملفات Compose، بما فيها override الكتاب ونفس وحدات البيانات. لا تستعمل `down -v`. حدّث المتصفح.

إذا كان الراوتر السابق LLM متوافقًا، يبقى اختياره كما هو. إن ظهر طلب إعادة الإعداد، اختر المزوّد المدعوم وموديل LLM وأدخل مفتاحه واحفظ؛ لا حاجة إلى تنزيل حزمة ZIP أو تثبيت الملفات يدويًا. لا يفعّل التحديث راوترًا كان معطّلًا ولا يختار مفتاحًا نيابة عن المالك.
