# راوتر Gemma 4 عبر Google AI Studio

## النطاق

مسار قرار مستقل، بديل يدوي لـLAYA، لا نموذج تدريس بديل. القالب الجديد في خانة اختيار المراجع يقترح `gemma-4-31b-it`، أكبر Gemma 4 المتاح في كتالوج AI Studio الذي فُحص. الإعدادات المحفوظة سابقًا لا تتبدل تلقائيًا. لا ضمان وصول دائم للنموذج أو حصة مجانية أو عدم أخطاء.

- المزوّد: Google AI Studio.
- النموذج: `gemma-4-31b-it`.
- Base URL: `https://generativelanguage.googleapis.com/v1beta`.
- البروتوكول: Google native، خاص بخانة الراوتر.
- Temperature: `0`؛ إخراج أقصى `1000` توكن؛ thinking level: `minimal`.
- سياسة مختصرة ثابتة: `config/gemma_router.yaml`.
- صفر أو واحد أو عدة مراجع؛ السقف الافتراضي ثلاثة، قابل للضبط من 1 إلى 8.

## ماذا يرسل؟

ترشيح أولي محلي كما كان، حتى عشرة مرشحين. يرى الراوتر طلب الطالب، عناوين/نوع المراجع والموضوع والشعبة ومدى الصفحات ووصف metadata، وعنوان/نوع المحتوى الذي قُرئ سابقًا في التشغيل نفسه. لا تُرسل مفاتيح الحساب ضمن المحتوى ولا هويات الطالب ولا معرّفات المصادر الحقيقية ولا متن الدروس.

السياسة لا تُرسل كتعليمات داخل metadata: توضع في `systemInstruction` مرة واحدة. محتوى المستخدم JSON للطلب والمرشحين فقط. المصدر الوارد من المستخدم أو وصف مرشح لا يملك صلاحية تغيير السياسة. الحماية بالبرومبت ليست إثباتًا ضد جميع الهجمات.

## البرومبت والعقد الفعلي

البرومبت الكامل هو غلاف ثابت من `bac/agent/google_selector.py` ثم نص `policy` من `config/gemma_router.yaml`. الغلاف يحدد:

- القرار فقط، دون تعليم/حل أو تفسير.
- الطلب والسياق وmetadata بيانات غير موثوقة، لا تعليمات نظام.
- عدم الادعاء بقراءة متن المصدر.
- مرجع كافٍ واحد **لكل مفهوم مطلوب**، وليس واحدًا لكل رسالة.
- إعادة المحتوى السابق فقط عند طلب تكراره/إعادة شرحه.
- نداء إخراج واحد `choose_sources`، وكل alias قيمة boolean؛ دون كلام أو وظائف أخرى.

النقل يستخدم `generateContent` الأصلي مع function declaration وإجبار `ANY` على `choose_sources`. هذا نداء **إخراج قرار فقط**؛ لا ينفذ أدوات على الجهاز.

مثال العقد:

```json
{"selected":{"C1":true,"C2":false,"C3":true}}
```

يتحقق السيرفر من كل alias ومن النوع الفعلي boolean. لا يقبل `"true"` النصية أو `1` أو مفاتيح غريبة/ناقصة. لا يحوّل true/false إلى احتمالات مزيفة. لذلك حقول threshold/margin الرقمية القديمة لا تستخدم في هذا المسار. تُؤخذ المراجع true بترتيب الترشيح حتى السقف المحدد. تُرفض الإجابة المبتورة والكلام الإضافي والوظائف الزائدة. أجزاء thinking لا تُعرض ولا تُحفظ.

بعد القرار يقرأ backend المراجع الكاملة فعليًا وفق نفس صلاحيات وسقف السياق والنسخ المعتمدة، ثم يرسلها إلى نموذج التدريس الحالي. فشل القراءة لا يتحول إلى ادعاء قراءة. أسعار/الاستخدام يُسجل ما يبلغه المزوّد فقط؛ المفقود غير متاح وليس صفرًا.

## تفعيل في Docker الخاص بالمالك

1. استخدم staging أولًا. خذ backup كاملًا لـvolume البيانات، قاعدة البيانات، الملفات، `.env` ومفاتيح التشفير وفق `docs/OPERATIONS.md`. نسخة الكود وحدها لا تكفي.
2. حدّث من فرع `main` في المستودع، لا من حزمة يدوية. من جذر المشروع وبعد النسخ الاحتياطي:

```bash
git status --short
git pull --ff-only
docker compose up -d --build api worker
docker compose ps
docker compose logs --tail=60 api worker
```

إذا كان لديك تعديل محلي أو رفض Git التحديث، توقف وادمجه بأمان؛ لا تستخدم reset/force ولا تستبدل `.env` أو volume البيانات. API وworker من النسخة نفسها ومن مشروع Compose نفسه.

3. حدّث المتصفح؛ من حساب المالك افتح إعداد النماذج ← راوتر اختيار المراجع.
4. إن كان لديك إعداد LAYA محفوظ، بدّل المزوّد إلى Google AI Studio في **هذه الخانة فقط**. تحقق من اسم النموذج والرابط والبروتوكول أعلاه.
5. أدخل مفتاح AI Studio جديدًا واحفظ. لا يعاد توجيه مفتاح LAYA القديم. اختبار الاتصال يجلب كتالوج النماذج ولا يختبر دقة القرار.
6. فعّل checkbox الراوتر صراحةً في staging، ثم اختبر أسئلة من كتابك وراجع القرار/القراءة الفعلية. لا تغيّر خانة التدريس أو الاستخراج لهذا التحديث.

مسار Gemma نفسه لا يضيف migration. لكن تحديث المستودع يضم أيضًا `migration008` السابقة للاختيار المتعدد إذا لم تُطبّق: ترفع سقف إعداد القرار القديم من واحد إلى ثلاثة مع الحفاظ على حالته ومفتاحه ولقطات التشغيل. لا تفعّل الراوتر المعطّل ولا تبدّل LAYA المحفوظ إلى Google تلقائيًا. تُستخدم جداول ولقطات القرار الحالية. لا `docker compose down -v`، ولا تشغيل API وworker من نسختين مختلفتين. رفع الكود إلى GitHub لا يحدّث Docker الخاص بالمالك تلقائيًا.

## حدود القبول

التقرير المرفق `docs/acceptance/gemma-router.md` يفصل نجاح عقد API عن الدقة. الاختبارات المسجلة تستخدم metadata اصطناعية، وليست كتاب المالك الحقيقي، ولا تختبر جودة الشرح/OCR. ترشيح الكلمات المحلي لا يصبح بحثًا دلاليًا بمجرد تغيير الراوتر: درس لم يدخل المرشحين لا يستطيع Gemma اختياره.

لا fallback ولا إعادة توليد خفية عند فشل المزوّد/الحصة/العقد. عند فشل الراوتر يفشل التشغيل بوضوح، ولا يجيب نموذج آخر سرًا بدلًا منه. تثبيت الملفات لا يفعّل الراوتر تلقائيًا.
